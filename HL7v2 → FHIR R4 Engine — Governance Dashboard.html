Pipeline Architecture

One atomic transaction Bundle carries a Patient, Encounter, and Observation from source message to server.

Why a transaction Bundle

The Patient, Encounter, and Observation are posted together as one atomic unit rather than three separate calls. Before any resource has a real server ID, urn:uuid references let the Observation point at "the Patient in this same Bundle" and "the Encounter in this same Bundle." If any one resource fails server-side validation, the whole transaction rolls back — so the server never ends up holding an Observation with no matching Patient.
